# Hidden-terminal output: bounded pipeline slice

1. Where we are: actual producer metrics show jobs finishing in roughly0.12seconds, while hidden terminal pages parse once per second and one run takes11.30seconds. Selected terminal completes around0.31seconds. This fix is source-tested; parent must measure three native repeats after rebuilding.
2. Changed: Page `readPipe` no longer waits for every individual tiny chunk before requesting another. It queues only bounded public xterm writes, retains every callback, and stops reading when the payload/count ceiling is reached. No xterm internals, vendor modifications, or global timer preferences changed.
3. Overall: real terminal tabs should continue processing bounded output without hidden-tab timer delays multiplying by every small pipe chunk.
4. Not claimed: browser timer throttling is not disabled, hidden drawing isn't forced, native performance improvement isn't assumed, and stdout/stderr are still separate streams with no invented cross-stream ordering.
5. Bounds and tests: per stream, at most256KiB UTF-16 payload and64 writes; reserve64KiB+8bytes (including streaming decoder carry) before each default read. With stdout+stderr, at most512KiB queued string payload, plus bounded transport buffers and capped callback records. Larger-than-supported reads fail visibly, not silently. EOF/read errors wait for earlier output; synchronous callback/throw cannot decrement twice. Pagehide/beforeunload cancel blocked reads/waiters and remove listeners. No reusable unresolved Promise.race is accumulated per read. New output-pipeline tests cover payload/count ceilings, ordering, Unicode/ANSI strings, EOF, synchronous callbacks, callback+throw, delayed callback after throw, read failure, oversized read, two streams, unload and blocked-read cancellation. Polish, search, wiring and diff checks also pass. Tests do not claim an OS UTF-8 decoder acceptance result.

Source basis and next: official xterm6.0.0 `src/common/input/WriteBuffer.ts`, SHA256 `c1c7726e5271fd37f254768a3a21323c1edc2a9bef52a55800dc20652285910f`, schedules an empty queue with setTimeout and processes queued work in12ms turns. Parent rebuilds then runs three exact same native performance journeys. High reasoning, source bounds/race tests plus real native throughput/heartbeat/memory proof.
7. Drift: this is bounded producer/consumer flow control, not a larger scrollback, infinite buffering, background animation, or weakened performance budget.
